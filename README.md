# audit_postgres: триггеры и журнал изменений

Задание по теме: аудит изменений в таблице `users` с помощью триггеров

## В базу добавлены:

- `users` — основная таблица с сотрудниками.
- `users_audit` — журнал всех изменений (кто, когда, что поменял).
- Функция `log_users_changes()` — смотрит, какая операция была (INSERT/UPDATE/DELETE) и фиксирует
- Триггер `trigger_users_audit` — связывает таблицу и функцию: срабатывает после любого изменения строки.

## Требуется реализовать:
- автоматически фиксировать каждое изменение полей `имя`, `почта`, `роль` в таблицу `users_audit`
- автоматически обновлять `update_at` в`users` при любом изменении строки
- ежедневно в 03:00 AM выгружать изменения за предыдущий день в CVS-файл внутри контейнера
## Частые ошибки и как их исправить

- **«trigger already exists»** — значит, запущен только `CREATE TRIGGER`, а `DROP TRIGGER IF EXISTS` не выполнился. Решение: ALT+X или выделить оба куска и запустить вместе.
- **В журнале изменений нет INSERT или DELETE** — скорее всего, функция и/или триггер были только на `UPDATE`. Нужно проверить, что в функции есть конструкция с кодом `IF TG_OP = 'UPDATE'`, `ELSIF TG_OP = ....` и тд, в `CREATE TRIGGER` написано `AFTER INSERT OR UPDATE OR DELETE`
